# Persisted model reference

This is the API-facing reference for data Drift persists. The service manages tenant IDs, record IDs, timestamps, versions, and deletion markers. Clients supply domain fields and flexible JSON.

## Common record conventions

| Field                    | Client responsibility                                                       |
| ------------------------ | --------------------------------------------------------------------------- |
| `id`                     | Read-only UUIDv7 generated by Drift.                                        |
| `tenantId`               | Read-only; derived from the API key and never accepted from graph clients.  |
| `version`                | Read-only on create; send its current value for PATCH, DELETE, and restore. |
| `createdAt`, `updatedAt` | Read-only UTC timestamps.                                                   |
| `deletedAt`              | Read-only soft-delete timestamp; normal reads hide deleted records.         |
| `data`                   | Any valid JSON application payload.                                         |
| `metadata`               | Any valid JSON system/control payload.                                      |

## Vertex fields

| Field        | Required | Definition                                                            |
| ------------ | -------- | --------------------------------------------------------------------- |
| `type`       | yes      | Domain kind such as `device`, `service`, `document`, or `job`.        |
| `slug`       | no       | Human-readable identifier for URLs or references.                     |
| `externalId` | no       | Identifier from another system, useful for imports.                   |
| `title`      | no       | Display label without parsing `data`.                                 |
| `status`     | no       | Lifecycle state, defaulting to `active`.                              |
| `data`       | no       | Primary flexible payload; default `{}`.                               |
| `metadata`   | no       | Source, tags, sync hints, confidence, and control data; default `{}`. |

## Edge fields

| Field          | Required | Definition                                                         |
| -------------- | -------- | ------------------------------------------------------------------ |
| `fromVertexId` | yes      | Source vertex UUIDv7.                                              |
| `toVertexId`   | yes      | Destination vertex UUIDv7.                                         |
| `type`         | yes      | Relationship kind such as `runs`, `depends_on`, or `attached_to`.  |
| `status`       | no       | Relationship lifecycle state, defaulting to `active`.              |
| `data`         | no       | Relationship-specific payload, such as a role, quantity, or order. |
| `metadata`     | no       | System/control data for the relationship.                          |

Both endpoints must be active and belong to the authenticated tenant. A deleted vertex soft-deletes its active incident edges. Restoring a vertex never restores its edges automatically.

## Tenant and API-key fields

Operators create tenants with a unique `slug`, a display `name`, and `status`. The bootstrap CLI creates the first admin key. API keys expose `id`, `label`, `prefix`, `scopes`, `createdAt`, `lastUsedAt`, and `revokedAt`; their secret hash is never exposed. See [Architecture](../../ARCHITECTURE.md) for the complete storage and authorization rationale.
